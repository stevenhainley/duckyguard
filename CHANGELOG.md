# Changelog

## 2.1.0 (2026-11-11, not yet published)

### Added
- First hardware test: a Flipper Zero on macOS 26 (`docs/EVALUATION.md` section 0, `bench/hardware/`, `captures/hardware/`).
- Key press rules J, K, L and M. Injectors let go of each key within 1-2 ms; a run of such keys is now blocked at any typing speed, including randomised delays. On the Flipper, characters that got through fell from 11 to 4 at full speed and from 124 (not blocked) to 3-5 for a jittered payload.
- Hold new keyboards: an untrusted keyboard's keys are blocked from the moment it appears until you choose Keep blocked, Allow once or Always allow, or unplug it. 0 of 124 characters got through on a Flipper Zero in three runs. Keyboards are rescanned on the first key after a pause so a just-plugged device is held before its first key gets through. Hold length setting: 20 s, 1 min, 2 min.
- Lookalike check: duplicates of a connected keyboard and trusted keyboards with a changed serial are held; lookalikes of trusted models are flagged.
- Injector identity table with sources, USB vendor names (usb.ids under its BSD option), and a vendor-mismatch flag.
- ATT&CK mapping leads with T1674 Input Injection. Spotlight-to-Terminal opener signature. Reports include a Ducky-style reconstruction of what was typed.
- `incidents --json`, `export --format ocsf`, and a harmless test-payload pack in `test-payloads/`.
- Away mode, Record only, Lock the screen on a block, Restart if it stops, and a Secure Input notice.
- Timed pause: for 5 minutes, for 1 hour, or until you resume. A timed pause ends on its own and is not remembered across a relaunch.
- First run offers to trust the keyboards connected at that moment.
- Menu bar: an attention icon for the states where DuckyGuard is installed but cannot block (Can't block, Not protected, Recording only, errors); Keep Blocked and Allow Once for a held keyboard; pause choices; Mute Alerts; Settings…; About.
- A main menu, so Cmd+W, Cmd+M, Cmd+C, Cmd+A and Cmd+, work in the window; Cmd+1 to Cmd+4 switch tabs. No Cmd+Q, on purpose.
- "Was this you?" on a blocked incident, with Pause for 1 minute. Undo for Delete and Clear all in the Timeline.
- The duck: a 3D head drawn with three.js from a depth map of the engraving (Depth Anything V2 Small), with six timing readings tied to its parts, a key tape, and an ASCII view of the same picture. Source in `ui-src/`, texture from `packaging/make_plate_texture.py`.
- Errors on the dashboard page are written to the app's log.

### Changed
- The dashboard is rebuilt: one status word and one sentence beside the duck, the same status words in the window and the menu (Protected, Keyboard held, Blocking, Paused, Can't block, Recording only, Not protected), plain names for settings, and one word per thing (blocked, got through, held, Trust, Allow once, key press).
- The hold prompt's main button is Keep blocked. It says in a sentence that your own keyboard is off too and that doing nothing lets the keyboard type when the hold runs out.
- Settings regrouped into Protection, General, Access, Advanced and About. The duplicate Protection switch is gone (use Pause). OCSF export is a command-line feature only.
- The window is fixed size and dark only; its bar moves the window. Inspect Element is available only with `DUCKYGUARD_DEV` set.
- One notification per plug-in instead of two or three; a hold-ended notification only when the hold ran out unanswered.
- New menu bar and app icons, generated by `packaging/make_icons.py`.
- The incident list is kept in memory and re-read only when its folder changes; the dashboard no longer reads up to 100 files every second.
- Sounds, notifications and dashboard snapshots are handed to the main thread instead of running inside the keyboard tap.
- Each measured key press is given to the detector once (`HoldTracker`); a stale one is no longer reused while keys overlap. Listen-only mode measures key presses too.
- Docs: hardware numbers replace simulation claims where they differ (rule G did not fire at full speed on hardware). Install steps use Open Anyway; Control-click, Open no longer works on current macOS.

### Fixed
- A permission granted after launch now takes effect within about a second. Before, the tap was never rebuilt, so the window could show Accessibility as on while nothing was blocked.
- The update notice could never appear (the page read the wrong field).
- The window showed a protected status before any data had arrived, and ran a built-in simulation if it lost contact with the app. It now says "Starting…" or "Not connected".
- Messages sent to the page before it finished loading were lost.
- The injector note for a Flipper matched its serial-mode vendor id and never fired for a Flipper typing. The unverified Rubber Ducky vendor-id claim is removed.

### Security
- The safe test typed a line containing `curl ... | sh` followed by Return, system-wide, into whatever had focus. It now types one harmless sentence with no command, never presses Return, types only while DuckyGuard's own window is the key window, and stops if that window loses focus.
- The menu bar icon showed the protected state when DuckyGuard could not block. Those states now have their own icon, and Record only no longer reads as protected.
- Controls that turn protection down (Pause, turning Record only on, turning Hold new keyboards off, Trust, Always allow) ignore activation from the keyboard.
- First-run and README text said DuckyGuard only looks at timing. It also saves the text of bursts it blocks, on this Mac; the text now says so.

## 2.0.0 (2026-10-27)

- Detector: rule G (>= 40 keys/s, CV < 0.10 blocks at 6 keys), rule H (untrusted keyboard + >= 22 keys/s metronomic blocks at 6 keys), rule S (a burst already blocked stays blocked until a pause). Simulation only; see docs/EVALUATION.md.

A rebuild around one idea: only claim what the code does, and make what it
does visible.

### Detection
- New burst-based detector: keys per second, coefficient of variation of the
  gaps, key hold time, burst length, payload text and "untrusted keyboard just
  appeared", combined by seven readable rules. Every verdict carries its
  reasons and numbers.
- Fixes an evasion gap: evenly spaced
  25-40 ms payloads from an already-present keyboard with no shell pattern are
  now blocked at 8 keys (v1 scored them 0.65 and let them through).
- Slow but perfectly regular payloads (DEFAULT_DELAY 100) are blocked at 20 keys.
- Keystrokes synthesized by local programs (password managers, text
  expanders, dictation) are labelled "software-typed" and not blocked.
- Key auto-repeat and modifier keys no longer count as timing samples.
- Fixed: `timestamp=0.0` was ignored; the 12-key text window could never
  match the `curl -sL http` pattern.
- Decision cost: median 49 us per key in isolation, 14 us median in the live
  tap callback (measured, see `docs/EVALUATION.md`).

### Blocking
- Keys in a blocked burst are dropped inside the CGEvent tap (returned as
  None) and never reach an application. v1 only activated its own window and
  logged the keys. Needs Accessibility; with only Input Monitoring the app
  observes and warns and says so.
- Quarantine length is a setting (0.5-10 s, default 2 s).

### Keyboards
- Keyboard inventory from IOKit registry reads (3.5 ms) instead of an
  `ioreg` subprocess (200-400 ms).
- "Learn this device": trusted keyboards persist in
  `~/Library/Application Support/DuckyGuard/trusted_devices.json` (0600).
- Notification and Devices screen when an untrusted keyboard appears; vendor
  id notes for common injector boards.

### App
- New menu bar app: pixel duck icon with protected / paused / alert states,
  native window with a local HTML dashboard (Funnel fonts bundled), no HTTP
  server and no open port (v1 listened on 127.0.0.1:4848 with CORS `*`).
- First-run onboarding: what it does and does not do, live permission checks,
  deep links to the two System Settings pages, then the safe test.
- Overview with status, keystroke rhythm strip and a test pad; incident
  timeline with plain-English explanations and measurements; Devices;
  Settings (quiet mode, launch at login, opt-in update check, quarantine
  length, expert toggle); graceful error notices and toasts.
- "Test it safely" types a harmless sentence into the app's own window via
  Quartz events so the block can be watched without hardware.
- Export incident report (Markdown). Indicators, MITRE ATT&CK rows and a YARA
  rule appear only when the captured text contains something to base them on;
  v1 always emitted a rule with a generic `curl` string and a hard-coded
  "NEUTRALIZED & CONTAINED (Zero Command Execution)" line.
- All state in one owner-only folder; corrupt files are set aside, not fatal.

### Packaging and docs
- `packaging/build.sh`: tests, icons, py2app, ad-hoc signature, DMG with
  SHA-256, all into `dist/`. Install script and Homebrew cask template.
- `docs/INSTALL.md`, `docs/NOTARIZATION.md`, `docs/EVALUATION.md`,
  `docs/FEATURES.md`; README rewritten with a "what it does not do" section.
- Version is 2.0.0 everywhere.
- The app is Python + PyObjC; the earlier "Swift 5 + Python 3.12" description
  referred to the v1 WKWebView host, now under `legacy/`.

### Removed
- v1 Swift window host, localhost HTTP API, tkinter desktop app and rumps
  tray (moved to `legacy/`, not built).
- Claims that were not backed by code: "sub-100 ms interception", "zero
  command execution", "sandbox", PCAP/hex viewer, enterprise exporter, Pro tier.

## 1.0.0 (2026-10-26)

Initial release: pynput keystroke listener with a 12-key velocity/jitter
score, `ioreg` USB polling, focus-stealing "decoy" window, incident Markdown
and YARA generation, Swift WKWebView host with a localhost dashboard.
